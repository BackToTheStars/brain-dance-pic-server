# brain-dance-pic-server

Сервис хранит изображения, аудио, видео и pdf в MongoDB GridFS.

## Пересборка образа: yt-dlp и ffmpeg

В образе стоят `yt-dlp` и `ffmpeg` (перенос видео с YouTube, `POST /youtube/probe` и
`POST /youtube/download`). Версия зафиксирована в `Dockerfile` — `ARG YTDLP_VERSION`
и `ARG YTDLP_SHA256`.

**Образ нужно периодически пересобирать с новой версией.** YouTube регулярно ломает
извлечение, и зафиксированный yt-dlp в какой-то момент просто перестаёт скачивать —
починка выглядит как обновление этих двух `ARG`:

```
YTDLP_VERSION — тег релиза https://github.com/yt-dlp/yt-dlp/releases
YTDLP_SHA256  — строка для файла `yt-dlp` из SHA2-256SUMS того же релиза
```

Сборка сама проверит контрольную сумму и выполнит `yt-dlp --version`, поэтому
неверная пара версия/сумма роняет билд, а не прод.

`ffmpeg` нужен для склейки. Progressive-форматов, где видео и звук лежат в одном
файле, у YouTube больше нет, поэтому дорожки качаются по отдельности и склеиваются
в mp4; контейнеры совместимы, так что это remux (`-c copy`), без перекодирования.
Версия ffmpeg не пинуется — берётся из репозитория Alpine.

Для локальной отладки (`npm run dev:media` идёт на хосте, а не в контейнере) нужны
`yt-dlp` и `ffmpeg` на PATH машины; путь к yt-dlp можно задать переменной
`YTDLP_BIN`. Без ffmpeg скачивание пары дорожек не выполнится — probe при этом
работает как обычно.

## Токен для защищённых ручек

Токен требуют `upload`, `download-and-save`, `/stats`, `/files`, `/youtube/*` и — с волны 6 —
`DELETE /<тип>/:id`. Отдача (`GET /<тип>/:filename`) намеренно открыта: файл читает
браузер по прямой ссылке.

В токене лежит операция, и middleware сверяет её с ручкой: без заголовка — 401, с битым
токеном — 403, с токеном чужой операции — 400 `Invalid operation`. Операции:
`upload`, `download_and_save`, `delete`, `stats`, `list`, `youtube`.

Команды для выпуска токена в репозитории нет: `npm run token` звал `scripts/tokens.js`,
которого не стало ещё в `ec448c7`, и в BP-25 строка убрана из `package.json`. Токен
подписывается однострочником — из каталога `media`, операция подставляется вторым
аргументом (здесь `delete`, срок жизни 5 минут):

```
node -e "require('dotenv').config();const {getToken}=require('./modules/auth/lib/token');console.log(getToken(process.env.JWT_SECRET_STATIC,'delete',Date.now()+300000,'test'))"
```

Дальше — обычным curl:

```
curl -X DELETE -H "Authorization: Bearer <токен>" http://localhost:3011/images/<id>
```

## Список файлов: `GET /files`

Ручка админской таблицы (BP-18, часть 1). К типу медиа не привязана — тип здесь фильтр,
а не адрес, — поэтому живёт рядом с `/stats`, а не внутри `/<тип>`. Защита та же, что у
`/stats`, операция в токене — `list`; серверный прокси (следующая волна) подписывает его
так же, как для `/admin/media/stats`.

| параметр | значения | по умолчанию |
|---|---|---|
| `type` | `audios`, `videos`, `images`, `pdfs`; можно списком через запятую | все |
| `name` | подстрока: `filename`, `metadata.originalname`, `metadata.originalUrl`, `metadata.title`; регистр не важен, спецсимволы регэкспа экранируются | — |
| `minSize`, `maxSize` | байты, по реальному размеру файла в GridFS | — |
| `from`, `to` | дата: ISO-строка или миллисекунды; по `uploadDate` записи | — |
| `sort` | `uploadDate`, `filename`, `size`, `storedAt`, `accessCount`, `lastAccessAt` | `uploadDate` |
| `order` | `asc`, `desc` | `desc` |
| `page`, `limit` | целые: `page` до 10000, `limit` до 200 | `1`, `50` |

Ответ — `{ items, total, page, limit }`. В элементе есть и поля записи `Media`
(`filename`, `contentType`, `uploadDate`, `originalname`/`originalUrl`/`title` из
метаданных, `accessCount`, `lastAccessAt`, `src`), и то, что видно только сверкой с
GridFS: `size`, `storedAt`, `fileCount`, `missing` (запись есть, файла нет) и
`duplicate` (одноимённых файлов больше одного). Ошибки разбора query — 400, все сразу
одной строкой.

Пагинация серверная и обязательная. Типы — разные коллекции и разные бакеты, поэтому у
каждого берётся начало выдачи длиной `page × limit`, результаты сливаются в общий
порядок и режется страница; порядок устойчив — второй ключ сортировки `_id`.

Сверка с GridFS идёт по странице: записи отбираются и сортируются в своей коллекции, и
только потом одним запросом добираются файлы по именам этой страницы. Исключение —
фильтр по размеру и сортировка по `size`/`storedAt`: там соединение неизбежно раньше
отбора страницы, и делается оно одним `$lookup` на тип по всем записям, прошедшим
фильтр. Записи без файла в такую выдачу не попадают: размера у них нет.

```
curl -H "Authorization: Bearer <токен операции list>" \
  "http://localhost:3011/files?type=images&name=logo&sort=size&order=desc&limit=20"
```

## Учёт обращений

`GET /<тип>/:filename` считает обращения: `accessCount` и `lastAccessAt` в записи `Media`
(BP-18, часть 2). Считается только начало просмотра — запрос без `Range` либо с `Range`,
начинающимся с нуля, — и не чаще раза в `ACCESS_COUNT_WINDOW` (`config/media.js`, сейчас
3 минуты) на файл, одним условным `updateOne`. Иначе один просмотр видео дал бы десятки
записей, и цифра означала бы рваность сети, а не спрос.

Отдача остаётся без токена, и накрутить счётчик может кто угодно — это принято осознанно:
обращение к файлу и есть признак востребованности. У записей, сделанных до этой волны,
полей нет; первое же обращение их заводит, а в выдаче `/files` они читаются как `0` и
«не обращались».

## Осиротевшие файлы: `scripts/orphans.js`

Сирота — файл в GridFS, на который нет записи `Media`: через API он недоступен (и отдача,
и удаление сначала ищут запись и отвечают 404), но место занимает и виден в `byType`
из `/stats`. Скрипт ходит в ту же базу, что и сервис (`MONGO_URL` из `.env`).

```
node scripts/orphans.js                       отчёт по всем типам, ничего не меняет
node scripts/orphans.js --type=images         отчёт по одному типу
node scripts/orphans.js --delete --all        снести всех найденных сирот
node scripts/orphans.js --delete --type=videos
node scripts/orphans.js --delete --id=<id>    снести конкретные файлы
```

Без `--delete` скрипт только показывает. Голый `--delete` без цели (`--all`, `--type`
или `--id`) — ошибка, чтобы «снеси, что найдёшь» нельзя было запустить случайно.
Одноимённые версии, у которых запись `Media` есть, показываются отдельной строкой и
не удаляются: какая из них лишняя — отдельный вопрос (BP-13).

В контейнере — `docker compose exec media-app node scripts/orphans.js`.
